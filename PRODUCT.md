# Product

## Register

product

## Users

Consumers delegating a stressful or tedious customer-service chat while supervising a visible browser window. They may be impatient, distracted, or concerned about irreversible account actions, so the interface must make the next action obvious without hiding consequential choices.

## Product Purpose

Flying Pig handles customer-service conversations on the user's behalf, escalates to a human when useful, and pauses for explicit approval when a decision has meaningful consequences. Success means the user can configure the app once, describe a problem quickly on later visits, supervise only when needed, and leave with a clear outcome and evidence.

## Brand Personality

Calm, direct, protective. Flying Pig should feel like a trustworthy desktop utility that advocates for the user without adding operational complexity or performative AI behavior.

## Anti-references

- Dense developer dashboards that expose helpers, endpoints, browser automation, and diagnostics as the primary experience.
- AI-themed control rooms with neon color, glass panels, decorative metrics, or excessive status chrome.
- Template galleries and multi-step wizards that make users configure every run from scratch.
- Interfaces that hide irreversible actions or imply broader authorization than the user granted.

## Design Principles

1. Configure once, then get out of the way.
2. Lead with the user's problem, not the implementation.
3. Ask for attention only when the user can change the outcome.
4. Keep consequential authorization explicit and auditable.
5. Show one clear next action at every state.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Support keyboard navigation, visible focus, 4.5:1 body-text contrast, reduced motion, clear non-color state labels, and responsive layouts without horizontal overflow at 390px. Avoid urgency cues that depend only on sound or color.
